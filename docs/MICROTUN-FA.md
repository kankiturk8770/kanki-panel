# microtun — گزارش کار (نسخهٔ ۳.۱۸.۰)

## خلاصه
microtun یک VPN سبک UDP برای بازی است. از روی نسخهٔ اولیه (فایل `microtun.go`) کامل شد و به‌عنوان یک پروتکل جدا به پنل کانکی اضافه شد. با کد KLINK قاطی نشده است.

- **هستهٔ Go** (سرور و کلاینت لینوکس، برای تست): ریپوی `Labo`، پوشهٔ `microtun/`، شاخهٔ `ccr-60b93d01-qmyjux`
- **پنل کانکی**: ریپوی `kanki-panel`، شاخهٔ `ccr-60b93d01-qmyjux` (نسخهٔ 3.18.0)

## مقایسه

| | WireGuard | نسخهٔ اولیه | microtun v2 |
|---|---|---|---|
| سربار هر بسته | ۳۲ بایت | ۳۷ بایت | **۲۸ بایت** |
| هندشیک و forward secrecy | دارد | ندارد | **دارد (X25519 + کلید هر کاربر)** |
| تعویض کلید | هر ۲ دقیقه | ندارد | **هر ۲ دقیقه، بدون قطعی** |
| چند کاربر | دارد | فقط ۱ | **دارد** |
| هدر روی سیم | قابل شناسایی | ۸ بایت ثابت + شمارنده | **ماسک‌شده** |
| ارسال دوبارهٔ بسته‌های کوچک | ندارد | دارد | **دارد (حفظ شد)** |
| ریستارت سرور | وصل می‌شود | کلاینت خاموش می‌شد | **حدود ۵ ثانیه بعد وصل می‌شود** |

## ایرادهای نسخهٔ اولیه که درست شد
- حملهٔ replay که با یک بستهٔ ضبط‌شدهٔ قدیمی تونل را قطع می‌کرد و آدرس کاربر را عوض می‌کرد.
- کلید ثابت بدون forward secrecy.
- ۸ بایت ثابت و شمارندهٔ آشکار در هدر (اثرانگشت برای DPI).
- فقط یک کاربر.
- خاموش شدن کلاینت با ریستارت سرور (`connection refused`).
- نبود keepalive برای NAT اپراتور.

## در پنل
- بخش **microtun** زیر «سرویس‌ها»، تیک جدا در فرم کاربر، «روشن/خاموش برای همهٔ کاربران».
- هر سرور آن را داخل agent اجرا می‌کند: پورت UDP ۴۲۰۰ (برای سرورهای بعدی ۴۲۰۱، ۴۲۰۲ …)، اینترفیس `mtun0` و NAT. نصب جدا لازم نیست؛ فقط agentها را آپدیت کنید.
- تنظیمات: پورت، ارسال دوبارهٔ بسته‌ها تا ۳۰۰ بایت، فاصلهٔ ۲ میلی‌ثانیه، MTU ۱۴۲۰، و پورت/آدرس/خاموش‌روشن جدا برای هر سرور.
- ترافیک و آنلاین مثل بقیهٔ پروتکل‌ها شمرده می‌شود. کاربر حذف‌شده یا منقضی در sync بعدی (حداکثر حدود ۳۰ ثانیه) قطع می‌شود.
- **لینک تست**: کاربر را انتخاب کنید تا لینک `mtun://` او برای هر سرور نمایش داده شود.
- لینک در دادهٔ اشتراک با کلید `"mtun"` هست (برای اپ در آینده).
- آدرس هر کاربر در تونل ثابت است: `10.79.0.0/16` بر اساس شمارهٔ کاربر (در ۳.۱۹ از `10.77` عوض شد، چون لینک‌های GRE تانل‌ها `10.77.N.0/30` هستند).

## روش تست روی سرور واقعی
1. پنل را از شاخهٔ `ccr-60b93d01-qmyjux` نصب کنید و agentها را آپدیت کنید.
2. پورت UDP ۴۲۰۰ را در فایروال دیتاسنتر باز کنید.
3. برای یک کاربر تست microtun را تیک بزنید و از «لینک تست» لینکش را کپی کنید.
4. روی یک سیستم لینوکس:
   ```bash
   git clone -b ccr-60b93d01-qmyjux https://github.com/kankiturk8770/Labo.git
   cd Labo/microtun && go build -o microtun .    # Go 1.24 لازم است
   sudo ./microtun client -url 'mtun://…'                    # کل ترافیک از تونل
   sudo ./microtun client -url 'mtun://…' -route-all=false   # فقط شبکهٔ تونل
   ```

## نسخهٔ ۳.۱۹ (microtun 2.1)
این‌ها داخل بخش پدینگ تصادفی هندشیک اضافه شدند، پس کلاینت و سرور نسخهٔ ۲.۰ هنوز کار می‌کنند.
- **چند دستگاه برای هر کاربر:** تا سقف «تعداد اتصال» کاربر (اگر سقفی نباشد ۸). دستگاه اول آدرس خود کاربر را دارد و بقیه از سرور آدرسی از `10.80.0.0/16` می‌گیرند. اگر کاربر به سقفش رسیده باشد، دستگاه تازه صبر می‌کند تا یکی از دستگاه‌ها ۲۰ ثانیه ساکت بماند؛ دستگاهی که در حال استفاده است هیچ‌وقت بیرون انداخته نمی‌شود.
- **IPv6 داخل تونل** روی سرورهایی که خودشان IPv6 دارند (`fd79:4d54::/64` با NAT). کنار آن سرور در صفحهٔ microtun برچسب «IPv6» می‌آید.
- **عقب رفتن ساعت کلاینت:** اگر زمان هندشیک نزدیک ساعت سرور باشد (۱۲۰ ثانیه) و کلیدش تازه باشد، پذیرفته می‌شود. هندشیک ضبط‌شده و تکراری هنوز رد می‌شود.
- کلاینت لینوکس ۲.۱ (ریپوی Labo): برای دستگاه دوم روی همان سیستم، `-device` با یک اسم دیگر بدهید.
- **اپ:** اپ باید یک شناسهٔ دستگاه ثابت برای هر نصب نگه دارد (۸ بایت، بعد از `mtD1` در هندشیک) و آدرسی را که سرور در جواب می‌دهد (`mtA1`) روی کارت VPN بگذارد. جزئیات در `src/vpn/mtun.rs`.
